Lesson / 01 5 minutes

Your first file

vmac is modal, like Vim. It starts in normal state, where keys move and edit, rather than type. i enters insert state to type text; ESC goes back. The modeline at the bottom shows which state you're in.

SPC is the leader, as in Doom Emacs: press it, pause, and a list of everything that can follow pops up. You don't need to memorise anything to begin.

Not installed yet? The installer builds the latest release and makes ~/.config/vmac/.

Terminal
$ vmac notes.txt     # open (or create) a file
$ vmac               # or start on the dashboard
Try it
  1. Press i, type a few lines, then ESC.
  2. Move with h j k l: left, down, up, right. Arrow keys work too, but your hands stay put this way.
  3. Save with :w and RET, or SPC f s.
  4. Press SPC and wait. Browse the groups: f files, b buffers, g git, a the assistant.
  5. Quit with :q (:wq saves first). Plain vmac opens the dashboard, where SPC b h takes you back any time.

Lesson / 02 15 minutes

Editing, the Vim way

Edits in normal state are sentences: an operator (what to do) followed by a motion or text object (what to do it to). d deletes, c changes, y yanks (copies). w is a word forward, $ the end of the line, iw the word you're in, i( what's inside the parentheses.

So dw deletes a word, c$ changes to the end of the line, yi" copies a string's contents. Doubling an operator acts on the line: dd, yy. A count repeats: 3dd.

Yanks go to the system clipboard too, so p pastes what you copied in another app, and ⌘V works everywhere.

Try it
  1. Jump around: w b e by words, 0 $ the line's ends, gg G the file's, 5G line 5.
  2. Put the cursor inside some parentheses and type ci(. The contents go and you're typing their replacement. ESC when done.
  3. Press . somewhere else. It repeats your last change, the whole ci( and what you typed.
  4. Find on the line with f and a character, ; for the next. dt) deletes up to the next ).
  5. Search with /, then n N. * searches for the word under the cursor.
  6. Select with v (characters), V (lines) or C-v (a block), move, then d, y or >. In a block, I types on every line at once.
  7. Undo with u, redo with C-r.

Lesson / 03 10 minutes

Files, windows and terminals

Open vmac inside a git repository and that repository is your project. SPC SPC finds any file in it by typing a few letters of its path, with a preview. Every file you open stays open as a buffer; SPC , switches between them.

Windows split the screen, each with its own cursor. Terminals are buffers too, so motions, search and yank work in their scrollback.

The picker is modal as well: ESC lets you move through results with j k, and q closes it.

Try it
  1. SPC SPC, type part of a filename, RET. C-n C-p move through the results.
  2. SPC o p opens the file tree. RET opens, a adds a file, r renames, and git's changes show as letters beside files.
  3. C-w v splits beside, C-w s below. C-w h / C-w l move between them, C-w c closes one.
  4. SPC o t opens a terminal below. Type in insert state; ESC to scroll and search it; SPC o t again hides it.
  5. SPC f r reopens a recent file; SPC p p switches to another project.

Lesson / 04 10 minutes

Code with a language server

Open a Rust, Python, TypeScript, Go or C file and vmac starts its language server for the project. Errors get squiggles, the one under the cursor shows at the bottom, and the modeline counts them (E2 W1). Completions pop up as you type.

vmac looks for rust-analyzer, pyright, typescript-language-server, gopls and clangd on your PATH. Install the ones you use.

Installed one while vmac was running? SPC c R restarts the servers and tries the missing ones again.

TerminalFor Rust, say
$ rustup component add rust-analyzer
Try it
  1. On a function call, gd goes to its definition; C-o comes back.
  2. K shows its documentation. Any key closes it.
  3. gr lists every reference, previewing each.
  4. ]d / [d jump between errors. SPC c a on one offers fixes.
  5. SPC c r renames a symbol everywhere; SPC c f formats the file. Edits to other files open them unsaved, so you can look before :w.

Lesson / 05 15 minutes

Git, the magit way

SPC g g opens *git-status*: your branch and how far it is from its upstream, then untracked, unstaged and staged changes, stashes and recent commits. Each key acts on what's under the cursor, whether that's a whole section, one file or a single hunk.

In ordinary files, the gutter marks changed lines (green added, blue changed, red where lines went), and the cursor's line says who last changed it and when.

GitHub works through the gh CLI. Run gh auth login once and pull requests, reviews and issues open inside vmac.

Try it: a commit
  1. Change a file, save it, and press SPC g g.
  2. TAB on the file unfolds its hunks. s on one stages just that hunk.
  3. To stage only some lines, select them with V and press s. u unstages the same way; x discards, after asking.
  4. c c, write the message, C-c C-c. C-c C-k cancels; c a amends the last commit.
  5. P p pushes, setting the upstream the first time. F p pulls, b b switches branch, l l shows the log.
Try it: a pull request
  1. On a branch, SPC g n writes a pull request. The title and description start from your commits; C-c C-c creates it (pushing first if needed).
  2. SPC g p lists the repository's pull requests with their checks. RET opens one.
  3. d reviews its diff. c comments on a line; S submits the review as a comment, approval or request for changes.

Lesson / 06 10 minutes

Notes, the org-mode way

Notes are plain Markdown files in ~/notes. A heading that starts with TODO is a task; a date like <2026-11-12 Thu> anywhere puts the line on the agenda. That's the whole format, and every other Markdown tool can still read it.

Markdown files read like the rendered page outside insert state: the #s and stars hide until you type.

Keep them somewhere else with vmac.set_notes_dir("~/Documents/notes") in your config.

Try it
  1. From any file, SPC n c, type a task, RET. It lands in inbox.md as a TODO, and you're back where you were.
  2. SPC n d opens today's daily note. Write a heading or two.
  3. On a heading, SPC m t cycles TODO → DONE → plain. On a - [ ] item it ticks the box.
  4. SPC m d inserts a date: type fri, +3 or 12-24.
  5. TAB on a heading folds its section; S-TAB folds them all. M-h M-l promote and demote a heading with its subtree, M-k M-j move it.
  6. SPC n a opens the agenda: overdue, today, upcoming and open TODOs from every note. RET visits one, t marks it done.
  7. SPC m l inserts a [[link]] to another note; RET on it follows.

Lesson / 07 10 minutes

Ask, then review

When you're stuck, ask from where you are. vmac drives the real Claude Code, Codex or Gemini CLI over the Agent Client Protocol, in a pane beside your code. It reads your buffers, including unsaved edits, and every change it makes waits for your review.

Claude Code is the default; it needs Node (for npx) and your claude login. SPC a b picks another agent.

Start vmac from a plain terminal rather than from inside a Claude Code session; Claude Code won't nest.

Try it
  1. Select a few confusing lines with V, then SPC a s. Your question goes with the file, the line numbers and the code.
  2. In a file with errors, SPC a e. It sends the language server's diagnostics; the question defaults to “Fix these problems.”
  3. SPC a a opens the prompt. Type @ to attach another file; RET in normal state sends.
  4. When it edits, changed lines get a green band. ]h [h move between changes; ga accepts one, gx rejects it.
  5. SPC a r lists every change as a diff. gc comments on a line and SPC a S asks it to revise by your comments.
  6. SPC a h reopens an earlier conversation, including ones from the Claude Code CLI.

Lesson / 08 20 minutes

Make it yours, in Lua

Everything you've used so far is Lua in lua/core/, and ~/.config/vmac/init.lua loads after it, so your config can change any of it. Save the file and vmac reloads, keeping your buffers. If it doesn't load, you see the error and the last working version keeps running.

The primitives are in the vmac table; the core's state and functions are in core. SPC f P opens your config.

Try things live first: SPC ; evaluates a line of Lua, and print shows at the bottom.

Config / Lua~/.config/vmac/init.lua
-- A command, and a key for it.
vmac.command("insert-date", function()
  vmac.insert(os.date("%Y-%m-%d"))
end)
vmac.map("normal", "SPC i d", "insert-date")

-- A light and a dark theme, following the system.
vmac.set_themes("Catppuccin Latte", "Catppuccin Mocha")

-- Your own modeline: a list of { text, face }.
vmac.hooks.modeline = function()
  return {
    { core.inserting() and "I" or "N", "accent" },
    { vmac.buffer_name(), "strong" },
  }
end

-- Let the assistant read and search without asking.
vmac.hooks.agent_permission = function(title, kind)
  if kind == "read" or kind == "search" then return "allow" end
end
Try it
  1. Paste the first block into init.lua, save, and press SPC i d.
  2. SPC h t previews the 36 built-in themes; :font NAME or SPC h F picks a font.
  3. Copy the example plugins in and open SPC h p. word-count adds SPC t w, zen adds SPC t z.
  4. :plugin-install URL clones a plugin from git. A plugin is just config in a folder: vmac.command and vmac.map, like init.lua.
TerminalFrom a checkout
$ cp -r examples/plugins/* ~/.config/vmac/plugins/

Lesson / 09 10 minutes

Sessions that keep running

Like tmux, each project opens in a session of its own, with its own buffers, windows, terminals, language servers and agent. Switch between them without one project's files cluttering another's buffer list.

Run them in a server and they outlive the window: close it, and terminals, builds and agents carry on until you attach again. On another machine, over ssh, the sessions run beside the files and only the window is here.

ssh has to log in without asking, with a key or an agent. vmac installs its server on the other machine the first time.

Terminal
$ vmac attach              # a window on the server, started if none runs
$ vmac attach ~/git/app    # ... on that project's session
$ vmac ls                  # the server's sessions
$ vmac connect me@devbox   # the same, on another machine
Try it
  1. SPC p p and pick a second project. It opens in a new session; the modeline starts with its name.
  2. SPC S s switches session; SPC S l goes back to the last one.
  3. Start vmac attach, run something long in SPC o t, then :q. Attach again and it's still running, where you left it.
  4. SPC S c adds another machine's sessions to this window. What you yank there lands on this machine's clipboard.
